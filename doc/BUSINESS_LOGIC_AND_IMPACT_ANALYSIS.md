## 1. Domain Business Logic Specification

### 1.1 User Entity Attributes

| Field | Type | Description | Mandatory | Validation Rules |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `string` | Unique identifier (e.g., `usr-101`) | System Generated | Immutable after creation |
| `name` | `string` | Full legal name of user | Yes | Min 2 characters, max 100 characters, trimmed |
| `age` | `number` | User age in years | Yes | Integer only, min 0, max 120 |
| `city` | `string` | City of residence | Yes | Non-empty string, trimmed |
| `state` | `string` | State or territory | Yes | Non-empty string, trimmed |
| `pincode` | `string` | Postal code | Yes | Min 4 characters, max 10 characters, alphanumeric |
| `createdAt` | `string` (ISO 8601) | Timestamp of creation | Optional | Auto-generated by backend/mock API |
| `updatedAt` | `string` (ISO 8601) | Timestamp of last modification | Optional | Auto-generated by backend/mock API |

### 1.2 Form Validation Rules (`UserForm.tsx`)
1. **Name**:
   - Error: `"Name is required."` if empty.
   - Error: `"Name must be at least 2 characters."` if length < 2.
   - Error: `"Name must not exceed 100 characters."` if length > 100.
2. **Age**:
   - Error: `"Age is required."` if empty.
   - Error: `"Age must be an integer."` if not integer or `NaN`.
   - Error: `"Age must be between 0 and 120."` if < 0 or > 120.
3. **City**:
   - Error: `"City is required."` if empty.
4. **State**:
   - Error: `"State is required."` if empty.
5. **Pincode**:
   - Error: `"Pincode is required."` if empty.
   - Error: `"Pincode must be at least 4 characters."` if length < 4.
   - Error: `"Pincode must not exceed 10 characters."` if length > 10.
6. **Live Clearing**: When a user modifies a field that previously failed validation, the inline error is immediately cleared.

## 2. Redux Client Cache Contract (Zero-Refetch Policy)

To provide instant UI updates and minimize server overhead, the application operates under a strict **Zero-Refetch Policy**:

### 2.1 Fetch Initial Users
* **Trigger**: Mount of `<UserList />` when `initialLoaded === false`.
* **Flow**: Calls `GET /api/users` -> Stores in `state.user.users` -> Marks `initialLoaded = true`.
* **Subsequent Visits**: Navigating away and back to `/user` does NOT re-trigger `GET /api/users`. Data is read instantly from the Redux cache.

### 2.2 Add User Flow
```text
User fills /user/add ──► Validate ──► POST /api/users ──► Redux unshift(newUser) ──► Navigate to /user ──► Toast
                                                                ▲
                                                [NO GET /api/users is called]
```

### 2.3 Edit User Flow (Critical Requirement #20)
```text
Click Edit on /user ──► Navigate /user/edit/:id ──► Look up id in Redux state.user.users
                                                           ▲
                                            [NO GET /api/users/:id is called]
                                                           │
                                                           ▼
                            User modifies fields ──► Validate ──► PUT /api/users/:id
                                                           │
                                                           ▼
                                            Redux update user in-place
                                                           ▲
                                            [NO GET /api/users is called]
                                                           │
                                                           ▼
                                            Navigate to /user ──► Toast
```
* **Fallback Behavior**: If a user bookmarks `/user/edit/:id` or opens it in a fresh tab where Redux has not loaded, the component renders `<ErrorMessage title="User Not Found in Cache" />` with a direct navigation button back to `/user`.

### 2.4 Delete User Flow
```text
Click Delete on row ──► Modal Confirmation ──► DELETE /api/users/:id ──► Redux filter out user ──► Toast
                                                                               ▲
                                                                [NO GET /api/users is called]
```

### 2.5 Row Selection Logic
* Selected IDs are stored separately in `state.user.selectedIds`.
* **Select All Checkbox**:
  * `checked = true` when `selectedIds.length === users.length && users.length > 0`.
  * `indeterminate = true` when `0 < selectedIds.length < users.length`.
  * Clicking Select All when partially or unselected selects all user IDs.
  * Clicking Select All when all rows are selected clears `selectedIds`.
* Deleting a user automatically removes their ID from `selectedIds` if selected.

## 3. Impact Analysis Matrix for Future Development

When modifying the codebase, consult this matrix to identify affected files and prevent architectural regressions:

### 3.1 Transitioning from Mock API to .NET 8 Web API + SQLite
| Impact Level | Minimal (Configuration Only) |
| :--- | :--- |
| **Files to Update** | `.env` or production environment variables:<br>`VITE_USE_MOCK_API=false`<br>`VITE_API_BASE_URL=https://your-dotnet-api.domain.com/api` |
| **Files Unaffected** | `src/components/*`<br>`src/api/user/userSlice.ts`<br>`src/api/user/userApi.ts`<br>`src/package/UI/*` |
| **Verification** | 1. Ensure .NET API allows CORS for the frontend origin.<br>2. Ensure .NET API exposes matching routes: `GET /api/users`, `POST /api/users`, `PUT /api/users/{id}`, `DELETE /api/users/{id}`, and `POST /api/auth/refresh`. |

### 3.2 Adding a New Field to the User Model (e.g., `email`, `department`)
| Impact Area | Affected Files | Action Required |
| :--- | :--- | :--- |
| **Types** | `src/api/user/userTypes.ts` | Add property to `User` and `UserPayload` interfaces. |
| **Validation & Form** | `src/components/User/UserForm.tsx` | Add state entry, `<Input />` component, and validation rules in `validate()`. |
| **List & Table** | `src/components/User/UserTable.tsx`<br>`src/components/User/UserRow.tsx` | Add table column header `<TableHeadCell>` and data cell `<TableCell>`. |
| **Mock Dataset** | `src/api/user/userMockApi.ts` | Add the new property to `INITIAL_MOCK_USERS` and payload mapping in POST/PUT. |
| **Backend** | .NET 8 Entity Framework Model | Add column to SQLite migration and DTOs. |

### 3.3 Adding a New Application Route / Menu Item
| Impact Area | Affected Files | Action Required |
| :--- | :--- | :--- |
| **Route Constants** | `src/constants/routes.ts` | Define path constant in `ROUTES`. |
| **Route Tree** | `src/app/routes.tsx` | Register child route inside `<Route path="/" element={<Layout />}>`. |
| **Sidebar** | `src/components/Layout/Sidebar.tsx` | Add `<NavLink to={ROUTES.NEW_ROUTE}>` and active styling check. |

### 3.4 Modifying Authentication or Token Refresh Window
| Impact Area | Affected Files | Action Required |
| :--- | :--- | :--- |
| **Configuration** | `src/constants/auth.ts` | Update `TOKEN_EXPIRY_BUFFER_SECONDS` or `AUTH_STORAGE_KEYS`. |
| **Interceptor Logic** | `src/api/common/authInterceptor.ts` | Ensure `refreshPromise` concurrency protection is preserved. |
| **Token Decoder** | `src/api/common/tokenHelper.ts` | Modify claim extraction if JWT claims change (e.g., role, tenant). |

## 4. Pre-Commit Architectural Checklist

Before submitting code changes, verify:
* [ ] **Strict Typing**: No `any` types introduced. All props and state are strongly typed.
* [ ] **Folder Structure Integrity**: No `pages/` or `features/` folders created.
* [ ] **No Unnecessary GETs**: No `GET /api/users` dispatched after create, update, or delete.
* [ ] **Edit from Cache**: `UserForm` in `mode="edit"` reads from Redux cache, never calling `GET /api/users/:id`.
* [ ] **No Page Refresh**: No `window.location.reload()` or full-page refreshes.
* [ ] **Persistent Layout**: Layout remains mounted during all user directory routing.
* [ ] **UI Decoupling**: Generic components in `src/package/UI/` contain zero User business logic.
* [ ] **Axios Interceptor Centralization**: No individual API methods manually attach Bearer headers.
